# verify-migration

`migrate-screen` の一連のサイクルとは独立に、特定画面の現新比較検証だけをやり直したい場合に使う
（実装修正後の再検証、リリース判定直前の最終確認など）。

## 実行手順

1. `$ARGUMENTS` からSCR-IDまたは画面名を特定し、`docs/screens/<SCR-ID>_<画面名>/` の設計書一式
   （`02_screen_design.md` `03_api_design.md`、既存の `05_test_spec.md` があれば）を確認する。

2. `test-engineer` エージェントを呼び出し、現新比較検証を実施させる。既存の `05_test_spec.md` がある場合は
   上書きせず、再検証結果として追記または版数を上げて更新する。

3. 不一致が見つかった場合:
   - 実装不備であれば、`backend-coder` または `frontend-coder` を呼び出して修正させ、修正後に再度
     このSKILLを実行して再検証する。
   - 意図した仕様変更であれば、`02_screen_design.md` の「10. 現行との差分・UX変更点」に記載があるか確認し、
     なければ追記する。

4. 検証結果のサマリ（一致/不一致件数、結論）をユーザーに報告する。リリース判定（人間承認ゲート）を
   通過できる状態かどうかを明示する。

## 注意事項

- このSKILLはリリース判定そのものを行わない。判定は必ずユーザーが行う。
